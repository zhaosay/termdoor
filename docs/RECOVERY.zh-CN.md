# 更新恢复与中心备份

## 更新前检查

先保存终端工作。网页更新会核对终端会话；手工运行更新脚本仍会重启服务。
工作区有任何未提交改动（包括删除和未跟踪文件）时，更新停止，不丢弃改动。

`update.sh` / `update.bat` 使用同一个更新工具：

1. 检查工作区与跟踪分支，只允许快进更新。
2. 获取新版本，在临时 Git worktree 中安装候选依赖（需要时运行 npm ci）。
3. 检查关键服务文件和本次改变的 JavaScript 文件的语法。
4. 再次核对当前工作区与提交，保存恢复点，然后快进当前版本并替换依赖。
5. 准备成功后重启；准备失败不执行重启。

临时 worktree 在准备结束后清理。恢复点保存在 Git 元数据目录的
`termdoor-update.json`；旧依赖目录为同目录下的 `termdoor-dependencies-*`。
它们不上传到 GitHub。保留旧依赖会占磁盘空间，确认新版本稳定后再清理。

首次升级到包含本工具的版本时，仍由旧更新脚本执行；下一次更新开始使用此流程。
依赖安装会执行候选版本的 npm 生命周期脚本，隔离 worktree 不是安全沙箱。

## 显式恢复旧版本

发现新版本运行异常时，先保存工作，并停止 TermDoor。然后运行：

```sh
node lib/update.js recover
```

恢复命令会：

- 拒绝覆盖未提交改动。
- 确认当前提交仍是恢复点记录的旧版或目标版。
- 新建 `codex/update-recovery-*` 分支指向旧提交，保留原分支与新提交。
- 如果更新保留了旧依赖目录，则恢复原依赖；替换下来的依赖也保留在 Git 元数据目录。

完成后用原启动方式启动服务，并核对实际运行版本与主要功能。
本命令不重启服务、不撤回配置或运行数据、不撤销应用任务。
如果更新前没有依赖目录，就没有旧依赖可恢复；需在恢复后的版本运行 npm ci。

这是显式恢复流程，尚未实现启动后健康检查失败的自动回滚。
macOS/Linux 的隔离演练已完成；Windows 的目录占用、原生依赖和启动行为仍需实机验证。

## 中心数据备份

服务器上运行（用自己的实际路径替换示例路径）：

```sh
node center/backup.js backup /path/to/center-data /private/backups/center-20261024.json
```

备份目录必须提前创建并限制访问；备份文件必须不存在。
工具创建权限为 0600 的备份，包含账号密码哈希、设备接入凭据、授权与接入码记录。
该文件是私密凭据材料，不放进 Git、网页目录或聊天，不公开分享。
Windows 需另行设置目录与文件 ACL，不能仅依赖 POSIX 权限位。

每个快照包含格式版本、时间与 SHA-256 校验。校验用于发现损坏，不是数字签名，
不能证明来源可信。快照不包含内存中的登录会话，不包含服务器环境变量、DNS、
HTTPS 证书、frps/nginx 配置或设备本机的应用配置。

## 恢复演练与正式恢复

```sh
node center/backup.js restore /private/backups/center-20261024.json /path/to/new-center-data
```

目标目录必须不存在，工具不会覆盖现有中心目录。恢复前验证格式与校验和，
新目录权限为 0700，数据文件为 0600。

演练时核对账号、设备、授权及凭据一致；不要让演练中心接管线上 frps 插件端口。
正式恢复时：保存工作，停止中心，将 TERMDOOR_CENTER_DATA 指向恢复目录，
启动中心，重新登录并核对设备与应用访问。原数据目录保留用于回退。
过期接入码不会重新有效，设备在线状态仍须以新的心跳和通路检查为准。

服务器本地快照不能抵御整台服务器丢失。异地备份需要额外安排安全存储与传输。
